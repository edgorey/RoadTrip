# Learning Log

Use this as an evidence ledger. Add dated entries after tests; do not rewrite old observations to match later conclusions.

## Seed learnings

### L-001 — Correct speech can be misheard

- **Status:** observed
- **Observation:** a correct response, exemplified by “Vasco da Gama,” was treated as incorrect.
- **Learning:** validation cannot assume a perfect transcript.
- **Rule:** confirm uncertain transcripts before a negative ruling; allow correction.

### L-002 — The host can validate a wrong answer

- **Status:** observed
- **Learning:** fluent delivery is not validation.
- **Rule:** validate before announcing correctness or changing score.

### L-003 — Premature scoring corrupts state

- **Status:** observed
- **Rule:** speaker, answer, and validation gate an atomic score update.

### L-004 — Simultaneous speech breaks turn logic

- **Status:** observed
- **Rule:** prefer named rotation; clarify overlapping responses without scoring.

### L-005 — Permission prompts damage momentum

- **Status:** observed
- **Rule:** continue until stop, planned transition, or mode boundary.

### L-006 — Rejection is design input

- **Status:** observed
- **Observation:** the object-advertisement game was disliked; some riddles underperformed.
- **Rule:** switch quickly, remember rejection, remove weak defaults.

### L-007 — Compact verbal formats fit naturally

- **Status:** reported success
- **Formats:** Quiz, 20 Questions, Who Am I?, Would You Rather?, Guess the Animal.
- **Next:** compare engagement and failure rates per format.

### L-008 — Personalization includes difficulty

- **Status:** working design principle
- **Learning:** players can share a topic at different cognitive levels.
- **Open:** how can adaptation avoid unfairness or condescension?


### L-009 — Reliability and freshness need different content sources

- **Status:** working design principle
- **Learning:** curated items improve answer reliability, repeatable testing, and difficulty control; live generation improves variety and personalization.
- **Rule:** prefer curated banks, extend through validated patterns, and generate live only with a preflight check.
- **Next:** measure repetition, engagement, and dispute rates for curated versus generated items.
